# ADR-001：正文抽取采用 App 内 WebView 渲染

- **状态**：已接受
- **日期**：2026-10-03
- **决策者**：高级架构师
- **相关角色**：产品经理（需求来源）、全栈开发（实现方）

---

## 背景

「收着」的核心功能之一是：**用户把公众号文章 / 头条文章转发进来，App 保存正文并做摘要提纯。**

这要求 App 能拿到网页**正文内容**。产品立项阶段曾假设"转发进来就能拿到文章"，
但**未经技术验证**。本 ADR 记录一次**实测**的过程与结论。

### 实测过程

对微信（`mp.weixin.qq.com/s/...`）与今日头条（`www.toutiao.com/article/...`）
分别做 HTTP 直接抓取测试，共 4 次（含带参数变体）：

| 对象 | HTTP 状态 | 实际拿到 |
|---|---|---|
| 微信文章（链接 A） | 200 | **正文完全空白** |
| 微信文章（链接 B） | 200 | **"参数错误"** |
| 头条文章（不带参数） | 200 | **内容完全为空** |
| 头条文章（带参数） | 200 | **内容完全为空** |

### 根因（来自社区已验证的技术分析）

**微信有三层防御**（参考 [wechat-article-viewer](https://github.com/Ranz-Feng/wechat-article-viewer)、[技术拆解](https://blog.csdn.net/be_racle/article/details/159737660)）：

| 层 | 原理 |
|---|---|
| Cookie 鉴权 | 需携带有效 `wap_sid2`，否则服务端拒绝 |
| 动态渲染 | 正文由 JS 动态插入 DOM，静态 HTML 里没有 |
| 反爬策略 | 检测 UA / Referer，非浏览器请求被拦 |

**头条**：详情页首次访问返回 JS，正文靠 JS 刷新显示；
且存在 JS 加密签名（`_signature` / `as` / `cp`），社区大量文章在讨论逆向破解。

### 备选方案评估

| 方案 | 结论 |
|---|---|
| HTTP 直接抓取 | ❌ 实测失败 |
| 真实浏览器渲染（Playwright/Puppeteer） | ✅ 有效，但**手机端跑不动 Chromium**（包体与内存不可接受） |
| RSS 中转（Wechat2RSS / wewe-rss） | ✅ 有效，但**需要服务器**，违背"零服务器"原则 |
| 模拟 Cookie 请求 | ⚠️ Cookie 会过期，需持续维护，体验差 |
| **App 内 WebView 渲染 + 注入 JS** | ✅ **选定** |

---

## 决策

**采用「App 内隐藏 WebView 渲染页面 + 注入 JavaScript 抽取正文」作为正文获取方案。**

### 理由

1. **WebView 本身就是一个真实浏览器**。对微信/头条服务端而言，它就是"一个真实用户在读文章"，
   因而**天然绕过三层防御**（Cookie、JS 渲染、UA 检测）与头条的 JS 签名问题。
2. **不需要服务器**，完美符合产品"零后台"的硬性原则。
3. **可复用用户登录态**，连 Cookie 鉴权问题都自然解决。
4. **微信与头条通吃**，任何"浏览器能显示的页面"都能抽取。
5. **不涉及 JS 逆向**，规避法律与技术双重风险。

### 实现要点

- 离屏 WebView（不可见、不参与布局），真实 UA，开启 JS 与 DOM Storage。
- 轮询等待目标节点出现（微信 `.rich_media_content`；头条 `article`；通用启发式兜底）。
- **超时 15 秒**，注入 JS 抽取标题 / 作者 / 时间 / 正文纯文本 / 首图。
- **字数校验**：少于 200 字视为抽取失败。
- **必须 `destroy()`**，且**串行执行**（同一时刻只跑一个 WebView），防内存泄漏与 OOM。

---

## 后果

### 正面

- 核心功能技术上可行，且无需服务器。
- 抽取能力可扩展到任何网页，不止微信/头条。

### 负面 / 代价（必须认账）

| 代价 | 应对 |
|---|---|
| **慢**：一篇 3–10 秒 | 异步抽取 + 乐观 UI（"正在收着…"），不阻塞用户 |
| **不稳定**：部分页面抓不到 | **强制降级路径**（见下） |
| **内存风险** | 串行 + 强制销毁 + 超时熔断；V1.1 评估独立进程隔离 |
| **需登录的页面** | 提示用户"在收着内打开一次登录" |
| **法律/道德边界** | 仅用于**个人保存**，不重分发、不做公开服务；README 明确声明 |

### 强制要求：降级是主路径的一部分

> **任何一条内容进来，都必须至少留下 `source_url`。**

| 抽取结果 | 数据层表现 | 用户看到 |
|---|---|---|
| 成功且字数充足 | `quality = good` | 正常摘要 |
| 成功但字数少 | `quality = poor` | "内容可能不完整" + 去原文 |
| 失败 | `quality = failed` | "仅存了链接" + 重试按钮 |

**绝不能因为某个页面抓不到就卡死或丢内容。**

---

## 被否决的方案（留档，避免重走）

| 方案 | 否决理由 |
|---|---|
| 服务端爬虫 | 违背"零服务器"原则，且维护反爬是长期负担 |
| RSS 中转 | 同上，且引入对外部服务的依赖 |
| JS 签名逆向 | 法律风险高、维护成本极高、随时失效 |
| 只存链接不抓正文 | 丧失核心价值（无法摘要提纯） |
