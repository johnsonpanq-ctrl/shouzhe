# 收这吧 (ShouZheBa)

> 什么都往里丢，它替你存好、提纯、找回。
> 数据只在你的手机里，模型用你自己的 Key。

---

## 这是什么

一个安卓 App。你说一句话、转发一篇文章、记一笔小钱，它都收下：

- **一句话** → 自动判断是待办、账目还是笔记，到点提醒你
- **一篇文章** → 抓到正文、生成摘要、打上标签，以后一句话就能找回来
- **一笔小钱** → 记下来（1 块钱也值得记，因为输入成本几乎为零）

**没有服务器。没有账号。没有订阅。**你的内容不出手机，模型调用走你自己填的 API Key。

---

## 为什么做这个

市面上的工具各管一摊：滴答清单只管事、记账 App 只管钱、收藏工具只管文章。
**没有一个是"你随便丢，我来分"。**

而且它们都要上云、要订阅。这个项目的目标很具体：

> 做一个我自己天天用、数据在手里、Key 在手里、代码也在手里的工具。

### 实际验证情况

在 Android 14 模拟器上端到端跑通：

- 全新安装 → 空状态 → 录入 → 卡片出现 → 落库，全链路无崩溃
- **无 API Key 状态下**："午饭38.55餐饮" 由规则引擎解析 → 落库账目（未确认）→ 确认后计入账本
- **预览与实际解析同源**：「一笔账目（¥38.55 · 餐饮）」与落库结果一致
- **数据库迁移实测**：v0.6.0 覆盖升级到 v0.7.0，老账目一条没丢，`user_version` 正确升级
- **账本汇总口径实测**：三笔全待确认时汇总为空并提示"另有 3 笔待确认，没计入"；
  确认 12.00 与 38.55 后汇总显示 **-¥50.55**（手算核对一致）
- **截图记账降级实测**：未配置识图模型时，图片仍完整存下来并降级成"待整理的截图"
- **118 个单元测试全绿**（时间解析 / 规则解析 / 识图解析 / 识图配置 / 金额解析 / 账本区间 / 标签清洗 / 导出 / 备份解析）
- **无 Key 录入实测**：正常存入、零崩溃、不弹任何错（AI 环节安静降级，不影响录入）
- **导出实测**：CSV 带 BOM、金额是元、含换行的字段正确转义；
  JSON 备份经 Python 严格解析通过，金额存**分**（无损）
- **导入实测（真闭环）**：导出 → 清空 App 数据 → 导入 → **4 条数据完整回来**
  （金额 3855/1200 分无损、确认状态保留）；再导同一文件 → "新增 0 / 跳过 4"，**条数不变**

> ⚠️ **真机（红米 K80 / HyperOS）仍需验证**：离线语音的识别准确率、云端语音的实际体验、
> 后台提醒是否到点响、截图记账接真实多模态模型的识图准确率。这几项依赖真机系统实现与真实模型。

## 怎么装

### 方式一：直接装 APK

去 **[Releases](https://github.com/johnsonpanq-ctrl/shouzhe/releases)** 下载最新 APK，传到手机安装。

> ⚠️ 目前的 APK 是 **debug 签名**，适合自用与尝鲜，不适合作为正式发布产物。
>
> **安装时若提示"未知来源"或 Play Protect 风险提示，是正常的** —— 本 App 需要自启动、
> 精确闹钟、通知等权限来保证提醒准时。确认后继续安装即可。

### 方式二：自己编译

需要 JDK 17、Android SDK（platform 35 / build-tools 35.0.0）。

```bash
git clone https://github.com/johnsonpanq-ctrl/shouzhe.git
cd shouzhe
echo "sdk.dir=/path/to/Android/Sdk" > local.properties
./gradlew :app:assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

> 首次构建会下载依赖；`app/src/main/assets/asr/` 里的 24MB 离线语音模型已在仓库内，
> 无需额外下载。

## 首次使用必做：后台设置

**这是本项目最重要的使用说明。国产 ROM 的省电策略会杀掉后台，导致提醒不响。
代码解决不了这个问题，只能手动配一次。**

### 红米 / 小米（HyperOS）

| # | 设置项 | 路径 | 目标值 |
|---|---|---|---|
| 1 | 自启动 | 设置 → 应用设置 → 应用管理 → 收这吧 → 自启动 | **开启** |
| 2 | 省电策略 | 同上页面 → 省电策略 | **无限制** |
| 3 | 通知 | 同上页面 → 通知管理 | 允许 + **设为重要** |
| 4 | 锁定后台 | 最近任务 → 下拉"收这吧"卡片 → 点锁图标 | **已锁定** |

> ⚠️ **本项目只在一台红米 K80（HyperOS）上开发与验证。**
> 其他机型未经测试。若提醒不触发，请参照上面思路自行调整后台策略（华为/荣耀、
> OPPO、vivo 的设置路径不同）。

App 内「后台运行」页面会逐项引导你完成，并显示**上次提醒的实际偏差** ——
偏差过大说明后台被限制了。

## 配置模型（BYOK）

设置页填三个字段即可，支持任何 OpenAI 兼容端点：

| 供应商 | BaseURL | 推荐模型 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |

API Key 用 `EncryptedSharedPreferences` 加密存放，**不写日志、不上传**。

### 截图记账需要单独配「识图模型」

DeepSeek 这类是**纯文本模型，不支持识图**。所以设置页给识图留了独立的三要素配置：

- **留空 = 跟随主模型**（主模型本身是多模态时，什么都不用填）
- 主模型不支持看图时，单独填一组，比如：

| 供应商 | BaseURL | 多模态模型 |
|---|---|---|
| SiliconFlow | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-VL-72B-Instruct` |
| 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-vl-max` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4v-plus` |

> 没配也不影响存图：截图照样存下来，只是不会被识图 —— **不会出现"点了没反应"的假按钮**。

## 技术要点

| 项 | 方案 | 为什么 |
|---|---|---|
| UI | Kotlin + Jetpack Compose | 重度依赖系统能力，原生是一等公民 |
| 存储 | Room / SQLite，单库统一主表 | 四条线共享"收进来"这条主线 |
| 正文抽取 | **离屏 WebView 渲染 + 注入 JS** | HTTP 直抓微信拿不到正文（三层防御），WebView 本身就是真浏览器。见 [ADR-001](docs/adr/) |
| 提醒 | `setExactAndAllowWhileIdle` + 开机全量重排 | 排期不许出错 |
| 权限 | **最小集**，不碰短信、不碰通知监听 | 二者均为 Play 高危权限，会阻断侧载安装。见 [ADR-002](docs/adr/) |
| 模型接入 | OpenAI 兼容协议 + 三层结构化输出回退 | 一套代码适配所有供应商 |

### 三条设计铁律

1. **任何内容进来，至少留下链接。** 抓取失败也绝不丢数据，降级是主路径。
2. **记账必须二次确认。** 先落草稿，用户确认后才计入账本。错一次就失去信任。
3. **金额用整数存"分"。** 绝不用浮点 —— 对账差几分钱会让用户彻底不信这个 App。

## ⚠️ 数据安全：请自己备份

**本项目无服务器、无账号，数据 100% 在这台手机里**，且 `allowBackup=false`
（避免被系统传到你不认识的云上）。

这意味着：**手机丢了、刷机、误卸载 —— 数据就没了，没有第二份。**

所以设置页提供了两个导出出口，换手机前请务必用一次：

| 出口 | 内容 | 用途 |
|---|---|---|
| **导出全量备份（JSON）** | 所有内容和字段，金额存**分**（无损） | 留档 / 换机恢复 |
| **导出账本 CSV** | 只有账目 | 直接用 Excel 打开、报销对账 |

导出后会调起**系统分享面板**，你可以存到文件管理器、发给自己、或传网盘。
整个过程**不需要任何存储权限**（走 FileProvider 授权单个文件）。

**恢复**：设置页点「导入备份」，选一个 JSON 备份文件即可。
导入是**合并式**的：

- 重复的条目（`uuid` 相同）**自动跳过**，不会产生重复数据
- **绝不清空、绝不覆盖**你现有的数据 —— 不会出现"恢复数据把数据恢复没了"
- 导入前会先把当前数据另存一份作为保险
- 选完文件会先给你看"新增几条 / 跳过几条"，确认后才真正写入
